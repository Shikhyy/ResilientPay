
# Website Information Architecture and Navigation

## Purpose

The public site should explain the product from first principles without forcing the visitor through a conventional marketing funnel.

## Primary navigation

- System
- Demonstration
- Protocol
- Research
- Documentation

## Narrative order

```text
Problem
→ system concept
→ live failure demonstration
→ architecture
→ transport model
→ transaction state
→ security
→ reconciliation
→ evidence
→ documentation
```

## Navigation rules

Navigation should remain visible enough to orient the visitor, but it must not compete with the content.

Use section numbers and short technical labels to reinforce the research/infrastructure character.

## Deep links

Every major landing-page section should be addressable by a stable URL anchor.

Documentation pages should not require JavaScript to be discoverable.
