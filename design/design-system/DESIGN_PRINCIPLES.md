# Design Principles

> **Document role:** Normative UX/visual specification.

## 1. State before decoration

The interface should always make the important system state visible. Connectivity, authorization, storage, synchronization, and reconciliation are core product information.

## 2. Evidence before marketing

Claims should be supported by a real product demonstration, measured experiment, architecture diagram, technical note, or cited reference. Avoid inflated language.

## 3. Physical systems influence the visual language

The system operates across phones, NFC, Bluetooth, QR, SMS, and networks. Use diagrams and physical metaphors derived from real infrastructure instead of abstract decorative shapes.

## 4. Geometry creates hierarchy

Use rules, borders, scale, alignment, whitespace, and offset panels instead of shadows or excessive rounding.

## 5. Precision beats personality

Brand personality comes from consistency and editorial voice, not from playful decoration.

## 6. Honest uncertainty

A pending or partially reconciled transaction must look pending. The UI must never collapse "locally authorized" and "settled" into the same message.

## 7. One visual argument per section

A section should have one primary message and one supporting visual. Avoid collections of unrelated cards.

## 8. Interfaces should teach the system

The best screen explains what is happening without requiring a second technical document.

## 9. Motion represents state change

Animation is allowed when it communicates synchronization, transfer, loading, or transition. Decorative animation is not a goal.

## 10. Every screen is a research artifact

The application and landing page should make the architecture, constraints, and evidence understandable to a technically literate visitor.
