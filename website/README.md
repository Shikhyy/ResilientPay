
# ResilientPay Website

The website is the public product, research, and demonstration interface. It is not part of the payment execution path.

## Primary objectives

The website must:
1. explain the connectivity problem
2. explain the architecture
3. demonstrate the real prototype behavior
4. explain transaction states
5. explain the security model without exposing secrets
6. present research evidence honestly
7. provide documentation
8. provide Terms of Service and Privacy Policy surfaces
9. clearly distinguish research prototype behavior from regulated production capability

## Design

The website follows `design/website/`. It uses a technical editorial visual language rather than generic SaaS patterns.

## Product truth

All displayed metrics, system capabilities, product claims, partnerships, and research results must be real and traceable. Simulated demonstration data must be clearly identified as simulated.

## Development

Build the website after the underlying demo model and design specification are stable enough to avoid inventing states. The live demonstration should consume real simulator behavior where possible.
